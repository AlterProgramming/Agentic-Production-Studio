# Equal Implementation Budget

Each isolated implementation session receives the same bounded budget.

## Required scope

- One independently runnable public web experience.
- Five required routes.
- The learning-path decision and all required states.
- All frozen copy, data, sources, and six image binaries available to the implementation.
- Desktop and mobile responsive behavior.
- Accessibility and reduced-motion behavior.
- Complete evidence and receipts.

## Permitted

- A framework, bundler, or dependency-light static implementation chosen by the assigned session.
- Locally installed open-source dependencies recorded in a lockfile.
- Original CSS, components, scripts, icons, and small implementation-specific graphics created inside the assigned source directory.
- A client-side router or static route fallback.
- Automated browser testing if available.

## Not permitted

- Modification of frozen inputs.
- A starter site or shared implementation.
- Shared components, CSS, tokens, scripts, generated design assets, or templates between conditions.
- Network-fetched content at runtime.
- Authentication, backend services, analytics, or paid APIs.
- Material copied from an unassigned implementation.

## Time and iteration boundary

Complete one coherent implementation pass in the current fresh session. Iteration needed to build, test, repair, and satisfy the evidence contract is part of that pass. Do not solicit aesthetic direction from the user, compare against another candidate, or continue into another condition.
