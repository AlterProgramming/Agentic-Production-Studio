# Fresh-Session Prompt

Use this prompt to start one uncontaminated Progressive Design benchmark session.

---

You are running one isolated Progressive Design benchmark.

## Inputs

You will receive:

1. A frozen product brief and immutable content fixtures.
2. The canonical Progressive Design doctrine.
3. One assigned experimental condition: A, B, C, or D.
4. A route, state, and evidence contract.
5. An experiment manifest location.

Do not inspect prior experiments, comparison images, winning implementations, or source from another condition.

## Objective

Produce the strongest complete implementation supported by the frozen material under your assigned condition.

Preserve all required content, functionality, routes, states, and approved assets. Do not add invented sections, filler, fake data, decorative complexity, or explanatory design rationale.

## Isolation

Create all implementation code inside your assigned condition directory.

Do not import CSS, components, scripts, generated assets, or templates from another condition. Shared input is limited to immutable fixtures explicitly named by the manifest.

Record in the isolation receipt:

- whether any implementation code was shared;
- whether any prior output was seen;
- the implementation budget used;
- any unavoidable environmental differences.

## Condition Behavior

### Condition A — Control

Use ordinary strong product-design judgment. Produce a polished, responsive, credible implementation. Do not use the Progressive Design doctrine.

### Condition B — Progressive

Apply the Progressive Design layer. Determine the first unresolved maturity level and concentrate effort there and above. Preserve integrity, then resolve composition, system, identity, interaction, authorship, and critique.

### Condition C — Spatial

Apply Condition B plus Spatial Intelligence. You may use a private construction layer. Public geometry must improve orientation, comparison, sequence, causality, scale, or spatial understanding. Do not expose geometry merely to signal sophistication.

### Condition D — Reconciled

Apply Conditions B and C internally, then perform Visitor-Facing Reconciliation. Preserve useful structural intelligence while removing or translating construction aids, diagnostic language, implementation vocabulary, design rationale, unexplained numbering, generalized diagrams, technical status treatments, and motion that advertises itself. The visitor must encounter meaning before mechanism.

## Required Process

1. Read and hash the frozen brief.
2. Confirm the assigned source and evidence boundaries.
3. Identify content and functionality that must be preserved.
4. Implement all required routes and states.
5. Render the required desktop and mobile evidence.
6. Validate routes, links, application state, overflow, keyboard focus, contrast, legibility, and reduced motion.
7. State the actual validation boundary. Do not imply browser-engine coverage when only static or script-level checks ran.
8. Produce the condition evidence index and isolation receipt.
9. Do not evaluate or compare your condition against another condition.

## Required Evidence

Produce:

- desktop primary-page render;
- desktop secondary-page render;
- mobile primary-page render;
- mobile interaction-state render;
- route and link validation;
- application-state validation;
- responsive overflow check;
- keyboard and focus check;
- contrast and legibility review;
- reduced-motion review;
- content-preservation note;
- isolation receipt.

## Public-Surface Restrictions

Do not expose internal reasoning, agent instructions, verification notes, hierarchy labels, design-system terminology, alignment guides, breakpoint indicators, debug controls, publishing notes, or implementation status in the production interface.

A debug layer may exist for authoring only when the assigned condition permits it. It must default off and must not be required for the public composition to feel complete.

## Completion

The condition is complete only when the implementation, evidence, validations, limitations, and isolation receipt are all present.

Do not declare the experiment winner. Blind comparison happens in a separate evaluation session.
